# Bitify Music — SEO audit & action plan

**Date:** 2026-11-22
**Scope:** `bitifyy.vercel.app` (single-page Next.js marketing site)
**Methodology:** claude-seo 10-principle synthesis (PERCEIVE → ANALYZE → VALIDATE → ACT), applied from the skill's published framework. The repo itself is a Claude Code plugin (`/seo` commands), so its slash commands were not runnable in OpenCode; its methodology and checklists were applied directly.

---

## PERCEIVE — observed signals

### Site (raw, before changes)

| Signal | Finding |
|---|---|
| Canonical origin | `metadataBase = https://bitify.music` — **NXDOMAIN** (verified via public DNS). Every canonical/OG URL pointed at a domain that does not exist. |
| Indexing | `robots.txt` allowed all crawlers but **no Sitemap directive**; no `sitemap.xml` existed. |
| Structured data | **None** — no JSON-LD for WebSite, SoftwareApplication, or FAQ. |
| Metadata | Title/description generic; no canonical alternates; no explicit index/follow. |
| Agent readiness | No `llms.txt`; no AI-engine-friendly summary of product facts. |
| GSC | HTML verification file added to the site root in a previous change. |
| Content surface | One indexable URL. Long-tail queries have no dedicated landing pages. |

### Competitors & niche research

- **Direct category leaders** (Spotify, Apple Music, YouTube Music, Amazon Music): compete on catalog, recommendations, social features, pricing, device coverage. Review sites (CNET, What Hi-Fi?, TechRadar, FreeYourMusic) rank them using *ease of use, cost, features, sound quality, device support*, usually in comparison tables with "best for X" framing.
- **Closest positioning competitor found:** Songstress (`songstress.app`) — *"Your music. Your server. Every device."* Their differentiators are **ownership, privacy, open source, quality formats (FLAC 24/96), gapless playback, cross-device handoff, offline, migration paths**. They publish concrete specs, prices, and source-backed facts.
- **Content pattern that ranks in this niche:** answer-first intros, spec tables, FAQ blocks, explicit dates/sources, clear single CTA, fast mobile pages, real product screenshots.
- **Cross-device continuity is a live theme in 2026** (YouTube Music only just rolled out desktop↔phone handoff) — "every screen" positioning is timely, but must be stated honestly.

### Assumption check (OBSERVE internal)

- Assumption: the site needs many new pages to rank. **Rejected for now** — a single-page site with a correct canonical, schema, and sitemap is the eligibility floor; page clusters come after the floor is fixed and traffic data exists.
- Assumption: "low traffic = bad content". Rejected — no traffic data was available from this machine (Vercel token expired, GSC not connected here); this plan does not guess at content performance.

## Highest-leverage constraint (THINK)

**The canonical origin pointed at a non-existent domain.** Until fixed, every other SEO/GEO improvement would be sending signals to the wrong URL. That went first.

## ACT — changes shipped (this commit)

| Priority | Change | File |
|---|---|---|
| Critical | Canonical origin → real live domain; canonical tag + index/follow; keyword-rich title/description | `src/app/layout.tsx`, `src/lib/site-config.ts` (`SITE_URL`) |
| High | `sitemap.xml` route + `Sitemap:` line in robots.txt | `src/app/sitemap.ts`, `public/robots.txt` |
| High | JSON-LD: WebSite, Organization, two SoftwareApplication entries (Windows + Android with real download URLs/versions), FAQPage | `src/components/site/structured-data.tsx` |
| Medium | `llms.txt` with canonical facts and product URLs for AI search | `public/llms.txt` |
| Medium | FAQ answer sharpened with the real platforms (Windows portable, ARM64 APK, TV) | `src/lib/site-config.ts` |

**Single source of truth:** when a custom domain goes live, change **only** `SITE_URL` in `src/lib/site-config.ts` (the sitemap and schema follow automatically), then update `public/robots.txt`, `public/llms.txt`, and the GSC property.

**Differentiation chosen (honest, from existing product facts):** cross-platform music player with direct portable Windows + APK downloads (no install), synced lyrics, playlists, listening stats, and TV experience — not "another Spotify clone". No invented specs, pricing, or testimonials were added.

## VALIDATE — falsifiability (how we know a bet failed)

| Bet | Success signal | Failure signal / fallback |
|---|---|---|
| Canonical fix | GSC shows `https://bitifyy.vercel.app/` as the canonical page with impressions | If GSC still reports `bitify.music`, a stale deployment is serving; redeploy and re-verify |
| Sitemap | `/sitemap.xml` returns 200; GSC Sitemaps report "Success" | 404 → check the route after deploy; domain mismatch → update `SITE_URL` |
| Schema | Rich Results Test / Schema validator parses WebSite, SoftwareApplication, FAQPage with no errors | Parse errors → check escaping of answer text; rich results are not guaranteed for FAQ on non-authoritative sites, but markup still aids AI extraction |
| AI search | `llms.txt` reachable; brand queries in ChatGPT/Perplexity return the correct canonical URL | Wrong URL cited → re-check canonical + llms.txt |
| Content sharpening | GSC impressions grow for "music player for desktop/android", "TV music app" | No movement after 6–8 weeks → the one-page surface is the ceiling; then build dedicated platform pages (Windows app / Android app / TV app) with unique copy |
